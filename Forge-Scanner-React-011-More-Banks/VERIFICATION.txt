FIVE DEFECTS FOUND ON THESE DOCUMENTS, AND FIXED
================================================================
  1. A Wells Fargo summary table puts the account number in its first column:
       Account number  Beginning balance  Total credits  Total debits  Ending
       4474485638      $74,953.21         $247,648.93    -$316,016.74  $6,585.40
     The account number was read as the opening balance, so the table could
     never balance.

  2. A Comerica summary is set beside a column of addresses and phone numbers,
     which rebuilding the rows interleaves into it. The branch telephone
     number, the PO box and the postcode were all read as amounts.

     1 and 2 are one rule: banks punctuate money and leave identifiers bare, so
     a figure counts only when it carries a decimal point, a thousands
     separator or a currency mark.

  3. In the same layout a row of the address column can land between a label
     and its figure ("Ending balance" / "period for this account is $0.00" /
     "$39,695.48"). The two are now paired across one intervening row, never
     across another label.

  4. Access FCU prints the figure ABOVE its own label ("$2,717.99" then "Ending
     Balance"). Labels and figures are now paired whichever is printed first.

  5. A Chase PDF whose text layer holds only structural markers
     ("*start*summary" "*end*summary") was not reported as needing OCR, because
     it had characters. A text layer with no printed amount at all is now
     reported as needing OCR — a statement always has amounts.

  Where credits and debits are equal and opposite, the figures alone cannot say
  which column is which; the header now does ("Total credits Total debits"),
  and where several layouts prove at once the busiest account wins, which is
  the rule already used between accounts inside one layout.

      "G & S METAL PRODUCTS CO., INC."  vs  "G&S Metal Products INC"
      "ESTAFF LLC"                      vs  "East Staff LLC"
      "GB OIL WHOLESALE CORP"           vs  "G Boil Wholesale CORP" (folder)
    a statement in a different entity's name
      Hammerhead Holdings' folder holds statements for EVERLAST ENTERPRISES
      INC and MAR LAM INDUSTRIES INC
    a name not found at all
      3 documents, mostly the activity printouts

  Stacking the suffix strip so "CO., INC." keys the same as "INC" was tried and
  reverted: it also turns "Test Company LLC" into "test", which would merge
  businesses that merely share a first word. Splitting one company into two
  leads is visible and recoverable; merging two is neither.

  This is reported, not fixed. It needs a decision about how names are matched.
