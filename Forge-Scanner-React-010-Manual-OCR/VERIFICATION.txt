WHAT CHANGED — OCR never starts on its own
================================================================
BEFORE (007 to 009)
  A regular scan silently fell back to OCR whenever a PDF had no usable text
  layer. The user was not asked and was not told it was happening; the run just
  took longer. An image file was failed outright with `ocr_required_for_image`.

NOW
  A regular scan reads the text layer. A file with no usable text layer is
  reported as needing OCR and left alone — not read, not failed. The menu then
  offers "Run OCR on flagged" with the count beside it, and that control reads
  exactly those files. The flag clears once a file has been read, so it is not
  offered twice. The scan mode is never changed by any of this: it stays on
  Regular. Setting the mode to OCR by hand still reads every file, unchanged.

  An image file is now reported as needing OCR rather than failed. The file was
  never the problem; it just has to be read a different way.

PROVED IN A REAL BROWSER (scripts/test-manual-ocr-browser.mjs, 12 checks)
  - the scanner starts with OCR off
  - a regular scan starts no OCR worker at all
  - a page with no text layer is reported as needing OCR, not read by it
  - such a file is not failed for having no text
  - a readable file is never flagged, and is still extracted normally
  - the Run OCR control reads the flagged file, and OCR really runs
  - the flag clears once the file has been read
  - the readable file is left alone by the OCR run
  - a manual OCR run does not change the stored scan mode
  - nothing reached the network and no page error was raised
