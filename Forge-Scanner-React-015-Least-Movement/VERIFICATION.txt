FOUR DEFECTS FOUND ON THESE DOCUMENTS, AND FIXED
================================================================
  1. A First Fidelity summary carries two equal statistics beside its totals:

       Previous Balance 10.00      Days This Statement Period 31
       9 Deposits/Credits 140,000.00   Average Ledger 7,622.90
       9 Checks/Debits   140,000.00   Average Collected 7,622.90
       Current Balance 10.00

     An equal pair like that can be added to both sides without disturbing the
     balance, so several readings balanced, the solver refused all of them, and
     the statement was reported as a MISMATCH — a claim that the bank's own
     arithmetic is wrong, which is far stronger than "could not prove".

     Where several readings balance, the one that moves the least money is now
     taken: treating those statistics as movements would invent deposits the
     bank never counted. A genuine tie is still reported as unsolved. Two
     statements moved from mismatch to reconciled.

  2. "Current Balance .43" — an amount under a dollar printed without its
     leading zero. The closing balance was never found. A decimal inside a
     larger figure is still not read as an amount of its own.

  3. "3319125179 $7,141.84 $119,387.30 -$126,808.58 -$279.44" — an overdrawn
     closing balance in a column table was read as positive, so the table never
     balanced. Both balances in a table now carry their printed sign, as they
     already did in a labelled block.

  4. "Apr 14, 2026 THORO CORP" — a transaction row dated with a month name was
     read as the company. The rule already rejected "04-13-2026 ..."; it now
     rejects both ways of writing a date.
