WHAT THE BATCH SHOWS — reported, not fixed
  The reliability work holds up on real documents: 61/61 files reached a final
  state, zero failures, zero timeouts, zero stalls, zero network access, in
  both modes.

  Extraction quality has three gaps that are NOT reliability defects and were
  NOT in the approved fix list for this build, so the v10 engine was left
  untouched:

  1. Company name is extracted for 0 of 61 documents. Because leads are grouped
     by company, this produces 61 separate leads instead of the 14 companies in
     the folder structure.

  2. All 61 documents are classified as `bank_statement`, including the 13
     files named `..._USE_THIS_APP.pdf`. Those files do carry a text layer
     (~1000 characters each); the classifier reports `no_statement_signal` and
     still falls back to `bank_statement` rather than `application`.

  3. Six documents have no text layer at all in regular mode (0 characters).

     account numbers (55 down to 47) where OCR misreads digits.

  Say the word and these become the fix list for 006.

================================================================
DEFECTS FOUND IN 004 AND FIXED HERE
================================================================
  1. The whole-file timeout did not exist. `SCAN_TIMEOUTS.jobMs` was declared
     and referenced nowhere. A file could be stuck indefinitely as long as each
     individual stage stayed inside its own smaller limit.
     Fixed: every attempt now runs under the watchdog at jobMs, on its own
     cancellation token, so the ceiling tears down whatever stage is running —
     including a stage that ignores cancellation entirely.

  2. A dead vendor load was cached forever. `pdfPromise.catch(...)` cleared the
     cached loader only on rejection. A script tag that fires neither `load` nor
     `error` leaves the promise pending, so the retry and every later file
     awaited a promise that could never settle.
     Fixed: one loader slot per library; a load that rejects, times out or is
     cancelled clears the slot and runs its cleanup, and the next attempt starts
     a fresh load.

  3. The delivered ZIP did not contain the offline dependencies its README
     described. It was 135 KB of source with no npm cache and no vendor assets.
     Fixed: the package now carries the cache, the vendor assets and the built
     dist/, and `scripts/package-release.mjs` refuses to build the ZIP if any
     of them is missing or empty.
