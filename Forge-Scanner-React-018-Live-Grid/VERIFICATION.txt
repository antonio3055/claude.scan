================================================================
WHY THIS BUILD EXISTS
================================================================
Build 017 added the same feature set (live results grid, zip upload, xlsx
export, storage panel) on a scaffolded TanStack Start app — full auth
system, embedded database, server-side rendering, none of which this
scanner uses. That stack produced three separate real Windows failures
across three rounds of real bug reports and fixes:
  1. "spawn vite ENOENT" — npm's Windows .cmd-shim issue in a build script.
  2. A production-only bug: package.json's "sideEffects": false let the
     bundler silently delete the entire ported engine (21 files kept only
     for their side effect of attaching to globalThis.ScannerEngine) —
     the production build shipped a scanner with no engine in it at all.
  3. After both of those were fixed and verified, Start still did nothing
     on the real machine, unreproducible from this sandbox.

None of these are scanner bugs — they are all fallout from machinery
(SSR, auth, an embedded database, a heavier bundler pipeline) the scanner
never asked for. 018 builds the same features directly onto 016's proven,
already-shipping Vite + React app instead. No new framework, no server, no
auth, no database — every one of the three failure classes above is
structurally impossible here.
